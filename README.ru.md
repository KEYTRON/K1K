# K1K — K1 Kernel

Язык: [English (основной)](README.md) | Русский

K1K — гибридное ядро ОС с нуля для x86_64, построенное на капабилити и
написанное на Rust (`no_std`). Это **не** форк Linux и намеренно не UNIX-like:
цель — взять лучшее из разных семейств:

| Откуда | Что берём |
|--------|-----------|
| Linux | скорость и прагматизм: одно привилегированное ядро, без лишних прослоек между ядром и железом |
| Windows NT / macOS XNU | гибридная структура: маленькое привилегированное ядро плюс подсистемы под надзором |
| seL4 / Fuchsia (Zircon) | капабилити вместо UID/ACL: задача может трогать только те объекты, на которые у неё есть handle |
| MINIX 3 / QNX | самовосстановление: сервисы изолированы в ring 3 и перезапускаются супервизором при падении |
| Redox OS | Rust ради memory-safety прямо в ядре |

Ядро владеет планированием, адресными пространствами, IPC и капабилити.
Всё остальное — драйверы, файловые системы, сеть, GUI — должно работать как
изолированные перезапускаемые сервисы.

## K1K и K1OS

K1K — ядро для [K1OS](https://github.com/KEYTRON/K1OS): «1» — это поколение
ОС, а не заглушка вида 0.x, поэтому здесь `1.0.0-alpha`. Сегодня K1OS грузит
Linux-ядро и использует собственный пакетный менеджер
[WARP](https://github.com/KEYTRON/WARP); план — шаг за шагом перевести K1OS
на K1K (загрузка → сервисы → user space, доставляемый WARP) по мере того, как
ядро обрастает драйверами и VFS.

## Что уже работает

- Загрузка по протоколу [Limine](https://github.com/limine-bootloader/limine)
  (BIOS и UEFI), лог в COM1 и в текстовую консоль на framebuffer.
- GDT/TSS, IDT с обработчиками исключений; исключение в ядре — паника,
  исключение в ring 3 — убивает только виновную задачу.
- Физическая память (bitmap PMM по карте памяти Limine), маппинг страниц ядра,
  отдельные пользовательские адресные пространства с общей верхней половиной,
  куча ядра.
- ACPI (RSDP → RSDT/XSDT → MADT), таймер Local APIC, откалиброванный по PIT,
  маршрутизация через I/O APIC с учётом override'ов из MADT; legacy PIC
  отключены.
- Вытесняющий round-robin планировщик (таймер LAPIC @ 1 кГц, квант 10 мс),
  потоки ядра, sleep/block/wake.
- SMP: дополнительные процессоры поднимаются по протоколу Limine MP, у каждого
  свои GDT/TSS, per-CPU блок (GS base, `swapgs` на каждом входе/выходе из
  ядра) и idle-задача; одна общая очередь готовых, задачи свободно мигрируют.
- Таблицы капабилити (`объект + права`, индексация по слотам) и синхронные
  эндпоинты сообщений с прямой передачей заблокированному получателю.
  Сообщение может нести капабилити (права ∩ маска, нужен `GRANT`) — это
  единственный способ передать полномочия между задачами.
- Объекты памяти: разделяемые наборы фреймов, которые задачи создают, отдают
  как капабилити и маппят в своё адресное пространство (`MAP_READ`/`MAP_WRITE`);
  DMA-вариант физически непрерывен и сообщает свой физический адрес.
- Капабилити на устройства: ядро перечисляет PCI, измеряет BAR'ы и отдаёт
  функцию задаче-драйверу, которая сама маппит MMIO BAR'ы. Ядро само с
  устройством не общается.
- Задачи ring 3 через `syscall`/`sysret`; 16 сисколлов: `log`, `exit`,
  `yield`, `sleep`, `send`, `recv`, `info`, `send_cap`, `cap_drop`,
  `mem_create`, `mem_map`, `ep_create`, `mem_create_dma`, `mem_phys`,
  `dev_info`, `dev_map`. Все регистры, кроме `rax/rcx/r11`, сохраняются через
  сисколл.
- Статический загрузчик ELF64: сервисы — обычные Rust-программы `no_std`,
  собранные с рантайм-крейтом `k1k-rt` (`user/`), права сегментов R/RX/RW
  выставляются по `PT_LOAD`.
- Поток-супервизор, который убирает мёртвые задачи и пересоздаёт упавшие
  сервисы из образа (с backoff).
- Сервисы в образе: `kbd` — драйвер PS/2-клавиатуры в ring 3 (ядро лишь
  пересылает сканкоды в эндпоинт); `blk` — драйвер NVMe в ring 3 (admin- и
  I/O-очереди на DMA-страницах, опрос завершений), который идентифицирует
  контроллер и читает диск; `hello`; `ping`/`pong` — запрос/ответ через
  эндпоинты плюс разделяемая страница, которую `pong` выделяет и отдаёт `ping`
  как капабилити; и `flaky`, который на каждой третьей итерации разыменовывает
  NULL и поднимается обратно без перезагрузки. Сервис, завершившийся с кодом
  0, считается выполнившим работу и не перезапускается.

```

[   blk] nvme ready: model "QEMU NVMe Ctrl" serial "K1K-NVME-0001", 32768 blocks x 512 B = 16 MiB
[   blk] sector 0: "K1K disk image v1 - read by the ring-3 nvme driver"
```

```

[ fault] task 6 'flaky' #PF addr=0x0 code=0x4 rip=0x40007d -> killed
[superv] service 'flaky' crashed (code -1) -> restarting (restart #1)
```

## Сборка

Нужны: Rust nightly (`rustup` подхватит из `rust-toolchain.toml`),
`xorriso`, `qemu-system-x86_64`, `make`, `git`.

```sh
make            # ядро + загрузочный ISO в build/k1k.iso
make run        # запуск в QEMU (BIOS), serial на stdio
make run-uefi   # запуск через OVMF
make test       # headless-самотест (-smp 4, NVMe-диск): проверяются перезапуски
                # супервизором, SMP-планирование и чтение диска из ring 3
```

`make run`/`make test` подключают 16 MiB raw-образ (`build/disk.img`) как
NVMe-контроллер для сервиса `blk`.

Первая сборка клонирует бинарники Limine в `third_party/limine`. `build.rs`
ядра сам собирает workspace `user/` и встраивает ELF сервисов, так что
достаточно `make` (или `cargo build` внутри `kernel/`).

Интерактивно: `make run`, затем печатать в окне QEMU — сервис `kbd` выводит
в лог каждую строку, завершённую Enter.

## Структура

```
kernel/           Rust-крейт ядра (x86_64-unknown-none, build-std)
  src/arch/x86_64 GDT, IDT, ACPI, LAPIC/IOAPIC, serial, переключение контекста, вход в syscall
  src/mm          pmm (фреймы), vmm (таблицы страниц / адресные пространства), куча
  src/sched       задачи и планировщик
  src/obj         капабилити
  src/ipc         эндпоинты
  src/syscall     диспетчер + доступ к памяти пользователя
  src/service     описания сервисов и супервизор
  src/loader      статический загрузчик ELF64
  src/console     консоль на framebuffer + макросы логирования
user/             workspace ring 3: rt/ (рантайм k1k-rt), svc/* (сервисы), user.ld
tools/            сборщик ISO, генератор шрифта
limine.conf       конфиг загрузчика
```

## Ближайший план

- Часы HPET/TSC, межпроцессорные прерывания (TLB shootdown, удалённое
  перепланирование).
- Капабилити на IRQ (прерывание → эндпоинт), чтобы драйверы не опрашивали;
  асинхронные уведомления.
- Файловая система поверх `blk` (сначала FAT только на чтение), сервис `fs`
  и запуск сервисов с диска — путь к загрузке user space K1OS.
- Отзыв капабилити; аллокатор для `k1k-rt`.
