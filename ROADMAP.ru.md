# Дорожная карта K1K

Стадия: 1.0.0-alpha.3

Этапы идут по порядку: `[x]` — сделано, `[ ]` — в планах. Текущий этап — первый незавершённый.

## Загрузка и базовое ядро
- [x] Загрузка через Limine (BIOS и UEFI), лог в COM1 и на framebuffer
- [x] GDT/TSS, IDT; исключение в ring 3 убивает только виновную задачу
- [x] Физическая и виртуальная память, отдельные адресные пространства, куча ядра
- [x] ACPI, таймер Local APIC, маршрутизация через I/O APIC
- [x] Вытесняющий планировщик (round-robin, квант 10 мс)
- [x] SMP: per-CPU блоки через GS base и `swapgs`

## Капабилити и драйверы в ring 3
- [x] Таблицы капабилити и синхронные эндпоинты IPC
- [x] Передача капабилити в сообщениях (права ∩ маска)
- [x] Объекты памяти и DMA-память
- [x] Капабилити на PCI-устройства, прерывания (ISA и MSI-X) и порты ввода-вывода
- [x] Драйвер клавиатуры PS/2 в ring 3
- [x] Драйвер NVMe в ring 3 с прерываниями MSI-X

## Сервисы с диска
- [x] ring 3 через `syscall`/`sysret`, 22 сисколла
- [x] Загрузчик ELF64 и рантайм `k1k-rt` для сервисов на Rust
- [x] Супервизор перезапускает упавшие сервисы (с backoff)
- [x] Файловый сервер FAT (только чтение) поверх NVMe
- [x] Сервисы грузятся с диска из `/SVC` через `spawn`

## Файлы и запуск сервисов
- [x] Файловый протокол (`open`/`read`/`stat`/`list` через разделяемый буфер),
  чтобы сервисы сами читали файлы
- [x] Передача капабилити и аргументов запускаемым сервисам в порядке
  манифеста, чтобы сервис находил свой файловый сервис по имени, а не по
  номеру слота
- [x] Манифест сервисов на диске вместо «всё из /SVC»: запускается только то,
  что перечислено в `/SVC/MANIFEST.TXT`
- [x] Куча каждой задаче ring 3 и `k1k-rt` как её глобальный аллокатор
  (проверен на хосте по своему списку блоков, `make test-heap`)
- [x] Один аллокатор на ядро и сервисы: крейт `k1k-alloc`, на хосте проверен и
  с фиксированной кучей сервиса, и с растущей кучей ядра

## Ядро: время, уведомления, отзыв прав
- [x] Асинхронные уведомления: объект `Notify` — счётчик событий с задачами,
  которые на нём ждут, так что событие, пришедшее до ожидания, не теряется.
  `SIGNAL` и `WAIT` — разные права; `irq_bind` умеет доставлять прерывание
  сигналом, что и использует клавиатурный драйвер в ring 3
- [x] IPI: TLB shootdown (перед освобождением адресного пространства и после
  изменения общей половины ядра) и удалённое перепланирование (проснувшаяся
  задача вытаскивает простаивающий CPU из `hlt`, а не ждёт следующего тика)
- [x] Часы HPET/TSC: TSC, измеренный по PIT и используемый только там, где CPU
  говорит об инвариантности; HPET, найденный в ACPI и на шине PCI, с
  замаскированными таймерами и посчитанной частотой; счётчик тиков как запасной
  вариант. База выбирается при загрузке, из неё построены сисколл `time` и
  `uptime_ms()`, а показания TSC всех CPU сверяются между собой. `make test-kvm`
  гоняет автотест на собственных часах хоста — единственное место, где этим путям
  можно верить: TCG не эмулирует ни то, ни другое
- [x] Отзыв капабилити: спавнеру сообщается, в какие слоты попали его выдачи,
  `cap_revoke` забирает капабилити обратно, отозванный слот — надгробие, которое
  не переиспользуется, а разбор задачи снимает её таблицу. Чтобы забрать что-то у
  чужой задачи, нужно `Control`, и оно проверяется раньше поиска задачи
- [x] Планировщик без единого глобального лока: своя очередь на каждый CPU,
  work stealing с ограниченным числом попыток, свои списки спящих задач, а таблица
  задач осталась только на медленных путях. Задача находится ровно в одном месте,
  и это один CAS на каждое перемещение. Пробуждение задачи, которая ещё стоит на
  стеке другого CPU, оставляется тому CPU; под локом не выполняется ничего, что
  может ждать другой CPU (задача создаётся до блокировки таблицы, все локи берутся
  с выключенными прерываниями); задача не подвешивается внутри прерывания,
  пришедшего из ring 3 — такой тик ждёт её следующего syscall
- [x] Возврат памяти загрузчика в PMM
- [x] Растущая куча ядра: окно в 1 GiB, на старте ничего не маппится, мегабайты
  берутся у PMM по мере надобности, а новые страницы объявляются остальным CPU
  после возврата прерываний

- [ ] Вытеснение ring-3 кода в произвольной точке, а не на syscall: для этого
  возобновление задачи, прерванной в пользовательском коде, должно разворачивать
  кадр трапы (как `ret_from_user` в Linux), а не делать обычный `ret`

## K1OS на K1K
- [x] K1OS загружается на K1K (boot-тест в CI на каждый push)
- [x] Доставка бинарников сервисов в `/SVC` пакетами WARP: каждый сервис — пакет платформы `k1k-x86_64`, а `make disk` собирает `/SVC` и `MANIFEST.TXT` через `warp --root … --platform k1k-x86_64 install` (WARP 0.4.12; сам WARP на K1K пока не запускается, нужна libc)
- [x] Терминал и shell поверх K1K: `kbd` шлёт клавиши в `sh`, тот отвечает через капабилити `Console` (`console_write`); команды `help echo ls cat uptime mem ver`, проверка вводом через QEMU (`make test-shell`). Запуск программ из него ждёт модель процессов и библиотеку C
- [x] Первая библиотека C для K1K (`libc/`): string/stdlib/stdio/ctype/errno/assert/time поверх небольшого слоя сисколлов на Rust (`user/libc-sys`); обычные программы на C собираются под `k1k-x86_64` и работают в ring 3 как сервисы (`user/c/chello`, доставляется WARP-пакетом; `make libc`, `make test-libc`)
- [ ] Полноценная libc (кандидат — musl): файловые дескрипторы POSIX, `getenv`, `time`, `malloc` на настоящих страницах, сокеты, когда появится сетевой стек
- [x] Сетевой драйвер: `net`, сервис virtio-net в ring 3 (современный virtio через PCI capabilities, новый сисколл `dev_config`); находит шлюз по ARP и пингует его в `make test`
- [x] DHCP-клиент в `net`: получает адрес, роутер и DNS (проверяется в `make test`)
- [x] У `net` теперь свой небольшой стек (Ethernet, ARP, IPv4, ICMP echo, UDP с контрольными суммами) и DNS-резолвер; сервис остаётся жить и отвечает на ARP и ping. DNS только пишется в лог, `make test` его не требует (в CI может не быть внешнего резолвера)
- [x] TCP-клиент в `net` (одно соединение, приём по порядку, отправка с повтором) и сокетоподобный IPC-протокол (`netproto`); сервис `nettest` в `make test` скачивает файл по HTTP с хоста; неблокирующий `recv` (сисколл 5, `nonblock`)
- [ ] Сетевой стек целиком: IP/UDP/TCP сервисом с сокетами через IPC, DHCP и DNS
- [x] TLS на K1K: BearSSL (в `third_party/bearssl`, MIT) собирается без ОС поверх нашей libc; `netget` в `make test` скачивает файл по HTTP и по HTTPS (TLS 1.2, ECDHE-ECDSA-AES256-GCM) с хоста, закрепляя открытый ключ сервера
- [ ] libcurl на K1K (нужна полноценная libc) — последнее, от чего зависит WARP
- [ ] WARP на самом K1K: `warp install` на целевой системе, а не со стороны хоста (сейчас `/SVC` собирается через `warp --root … --platform k1k-x86_64`)
- [ ] Необязательный сторонний антивирус: ClamAV (с явной пометкой, что он не наш) пакетом WARP, позже сервис `scan`, который `fs`/WARP спрашивают перед запуском бинаря, по образцу Defender; нужны полноценная libc и сокеты
- [ ] Сервис `warp-init`: при старте K1OS сверяет содержимое `/SVC` с хэшами из последнего подписанного индекса (`repos.json`) и докачивает дельту или полный пакет по сети. Правила: грузиться с диска как есть и не ждать сеть; качать в фоне, активации переключать на следующей загрузке; сервисы, на которых держится система (`fs`, `blk`, `net`, `warp-init`), обновляются рядом с пробной загрузкой и возвратом к последней рабочей версии (`warp rollback`); доверять только подписанному индексу, ключ которого зашит в образ. Первый шаг: сообщать о расхождениях с локальным индексом, без сети
- [ ] Драйвер GPU NVIDIA — сервис в ring 3 поверх прошивки GSP (по образцу драйвера nova в Linux), доставка через WARP

## Другие архитектуры
Сейчас K1K работает только на x86_64: весь код платформы (GDT/IDT, APIC, ACPI) написан под неё.
- [ ] Слой `arch/` отделён от общего кода ядра
- [ ] aarch64 в QEMU (`virt`): контроллер прерываний GIC, таймер ARM, загрузка через Limine по UEFI
- [ ] CI на aarch64
- [ ] Apple Silicon: контроллер прерываний AIC, загрузка через m1n1 и U-Boot
- [ ] RISC-V (riscv64) — когда появится реальная плата для тестов

## Мелкие известные недоработки
Шероховатости, замеченные по ходу; ничто не мешает текущей работе, но все стоит закрыть.
- [ ] `uptime_ns()` слишком грубый, чтобы измерить время сетевого обмена (ping показал «0 us»); нужны часы точнее для сервисов
- [ ] `net` не принимает прерываний: очереди virtio опрашиваются раз в миллисекунду; привязать вектор MSI-X устройства к эндпоинту сервиса
- [ ] У `net` нет таблицы маршрутов (всё идёт через шлюз), нет фрагментации IPv4 и поддержки legacy (transitional) virtio-net
- [ ] `net` обслуживает одного клиента и одно TCP-соединение, без слушающих сокетов и без UDP-сокетов по IPC
- [ ] DNS в `make test` только пишется в лог (в CI может не быть внешнего резолвера); локальный резолвер на стороне хоста позволил бы требовать его в тесте
- [ ] `make test-kvm` не гоняется в CI после изменений шелла, libc и сети
- [ ] WARP 0.4.12 опубликован только для x86_64: сборки aarch64 (OrbStack на маке), Termux (android_aarch64) и macOS остались 0.4.9
- [ ] Ссылка на raw-индекс GitVerse у WARP-репозитория `k1os` не проверена клиентом
- [ ] Незакоммиченные правки `ci/runner/*` в K1OS относятся к раннеру другого проекта и ждут решения владельца
- [ ] У TLS нет источника энтропии: `k1kc_entropy` берёт зерно из часов и TSC, это не стойкая случайность; драйвер virtio-rng (или RDRAND, где есть) и сервис `rng`
- [ ] TLS пока не проверяет цепочку сертификатов: на K1K нет часов реального времени и хранилища доверенных корней, поэтому `netget` закрепляет ключ сервера; нужны часы (RTC или NTP через `net`) и пакет WARP с корневыми сертификатами
- [ ] `net` одновременно использует одна программа на C (сервис держит одного клиента и одно соединение)
